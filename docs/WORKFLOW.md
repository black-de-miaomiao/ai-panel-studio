# 开发流程与工程化 AI 协作

## 开发流程

作业提出了通过 Claude Code 与 DeepSeek V4 Pro 协作开发的设想；我如实说明，本项目使用 Factory Droid（与 Claude Code 同类的 AI 编码代理）。我作为主代理负责理解需求、做关键决策、拆分阶段、编写 Prompt、审查结果并分层提交，luna-worker 子代理按约定执行。DeepSeek V4 Pro 是应用运行时的质量档模型，用于生成阵容和总结；DeepSeek Flash 是速度档模型，用于出价、发言、主持人和洞察。开发时我用真实 DeepSeek 做运行时 Prompt 冒烟调优与整场联调；单元、集成和 E2E 使用确定性的 mock，不依赖网络。

**SDD：先固化可执行的规格。** 我先将产品需求、数据模型、REST/SSE 契约、状态机、架构和纯函数规则写入文档，再把表结构、种子数据和 zod 契约代码化。审查重点是字段、事件、错误码、默认值和跨文档一致性；遇到规则未定义时先改规格，再让测试和实现跟进。这样每个新子代理都能从仓库获得同一事实来源。

**DDD：先定义体验，再连接真实数据。** 前端先按“深夜演播厅”设计规范拆组件与页面，以和真实 SSE 同构的事件剧本驱动 reducer。编排者逐视口检查截图和交互，再给出指向具体状态、元素和尺寸的续派；视觉修订中，静态页面拆分样式前后逐像素比较为零差异。随后前端接入 REST 与 SSE，尽量复用已经审过的状态流。提交按设计规范、组件页面、视觉修订、数据接入分层，避免把 UI、样式和协议问题混在一批改动中。

**TDD：先写失败测试，再实现。** Red 阶段用完整签名桩明确接口，Green 阶段按 core、LLM、Prompt、引擎与路由逐层补齐。测试对应规格中的边界、状态转换、事件顺序、并发隔离和安全约束；编排者审查失败原因，不能靠放宽断言换取全绿。真实模型输出还要人工通读：格式正确并不代表交锋、洞察和总结自然。提交按规格/契约、测试、实现和修复分层；规格发生变化时先同步规格与测试。07 的续派 2、3 又把真实运行问题转为可回归规则：换一批失败仍保留待开播阵容；interrupt 由 Runner 设定额度并避免相邻抢答；仅对出价格式解析错误重试一次；按最近三条专家正文中未出现过的行为增加调度多样性分。

**E2E：验证用户看到的闭环。** 计划用 Playwright 从浏览器经 Vite、Express、引擎、SQLite、SSE 再回浏览器，覆盖创建、确认、直播、暂停/继续、结束、回放、窄屏布局、重连和隔离。E2E 实际结果、最终用例数与提交数：（第二部分补齐）。

我也把验证按风险分层：类型检查先确认跨包契约，单测锁定纯规则和 reducer，集成测试再覆盖数据库事务、REST 错误体与 SSE 补发顺序；真实模型仅用于有次数上限的受控冒烟和整场联调，记录任务耗时、token 与可观察的质量，不把密钥或 reasoning_content 写进日志。视觉评审按“状态 × 视口”看图，先固定场景再比较布局，避免把流式字幕进度误判为样式回归。

## 典型问题与解决路径

1. **种子回放像机械轮播。** 首版专家按 seat 顺序发言、次数相同，洞察立场也对不上证据。原因是样例数据只满足结构，不满足讨论质量。编排者在 03b 中把交锋、发言次数差、抢答顺序、证据 seq 和 stanceTag 写成可验证要求，再修种子并补测试；提交 `ef7421e` 后，回放才成为可信的完整示例。
2. **Prompt 格式正确，讨论却不像圆桌。** 真实冒烟中专家很少反驳，主持人猜错嘉宾名单，洞察为空而总结仍说有共识。根因是模型只看到匿名别名，出价缺少立场关系，洞察只拿到新增发言。编排者先把阵容名册、上一条发言与立场、洞察窗口写进规格，再续派补 Prompt 和测试；之后逐行审查 mock 输出，又将引用、病句、重复和错误归属改写为断言。
3. **控制接口会覆盖实时状态。** 用户点击暂停时，页面曾用首次载入的快照替换 reducer，已由 SSE 收到的发言与洞察随之消失。原因是控制响应复用了过期快照，而不是合并最新状态。续派改为只合并 discussion，并比较更新时间；总结竞态另由 summary.completed 推进时间戳、避免旧响应倒退来修复，配套测试等待 SSE 连接实际建立。

## 我对工程化 AI 开发的理解

- **Prompt 是有版本的工程输入。** 我把每阶段原文留在 `docs/prompts/`，记录范围、验收与不能碰的目录；评审发现缺陷时追加精确续派，而不是让代理重写已完成部分。
- **规格先于行为变化。** 当测试或实现暴露状态机、失败计数或模型路由歧义时，我先说明决定并更新规格，再同步测试与代码，保留可追溯的因果关系。
- **分层验证互相补位。** 单测检查规则，集成测试检查数据库、REST 与 SSE，截图和真人通读检查真实体验；任何一层都不能替代其他层。
- **并行必须有边界。** 我将 server、web、docs 等任务分给不重叠的文件范围，验证命令也限定 workspace，避免共享 lockfile、工作区和服务状态被同时改动。
- **安全约束进入流程而非口头提醒。** 密钥只留在后端环境；真实模型的隐藏推理不进入小窗、事件或日志；mock 与假值承担自动化验证，真实模型只用于受控冒烟和联调。
