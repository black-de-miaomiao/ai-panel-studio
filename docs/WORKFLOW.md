# 开发流程与工程化 AI 协作

项目源码仓库（公开）：https://github.com/black-de-miaomiao/ai-panel-studio

## 开发流程

本项目使用 Factory Droid（与 Claude Code 同类的 AI 编码代理）因额度用完后续用DeepSeek Harness+deepseek（个人认为模型在原平台更好点）交接最后的收尾工作。主代理负责理解需求、关键决策、拆分阶段、编写 Prompt、审查结果并分层提交，luna-worker 子代理依约执行。运行时质量档模型 DeepSeek V4 Pro 生成阵容和总结；速度档模型 DeepSeek Flash 出价、发言、主持人与洞察。开发时以真实 DeepSeek 做运行时 Prompt 冒烟调优与整场联调；单元、集成和 E2E 用确定性 mock，不依赖网络。

**SDD：先固化可执行的规格。** 将产品需求、数据模型、REST/SSE 契约、状态机、架构与纯函数规则写入文档，表结构、种子数据与 zod 契约再代码化。审查重点是字段、事件、错误码、默认值与跨文档一致性；规则未定义先改规格，测试与实现跟进。

**DDD：先定义体验，再连接真实数据。** 前端先按“深夜演播厅”设计规范拆组件与页面，以与真实 SSE 同构事件剧本驱动 reducer。编排者逐视口检查截图与交互，给出指向具体状态、元素和尺寸的续派；视觉修订样式拆分前后逐像素零差异。随后接入 REST 与 SSE，复用已审状态流。提交按设计规范、组件页面、视觉修订、数据接入分层，防 UI、样式与协议问题混批。

**TDD：先写失败测试，再实现。** Red 阶段用完整签名桩明确接口，Green 阶段按 core、LLM、Prompt、引擎与路由逐层补齐。测试对应规格的边界、状态转换、事件顺序、并发隔离与安全约束；编排者审查失败原因，不靠放宽断言换全绿。提交按规格/契约、测试、实现与修复分层。07 续派 2、3 把真实运行问题转为可回归规则：换一批失败保留原阵容；interrupt 由 Runner 限额且不相邻；出价格式错误只重试一次；按最近三条专家正文未出现行为加调度多样性分。

**E2E：验证用户看到的闭环。** 用 Playwright 驱动本机 Edge，经 Vite、Express、引擎、SQLite、SSE 全链路，覆盖创建、确认、直播、控制、回放、布局、重连、隔离与密钥泄漏九个场景，另留默认跳过的真实模型场景。讨论 ID 是 mock 与 Runner 随机数唯一种子，统计性断言非对任意种子成立；用服务端种子变量固定，质量断言不靠重试。默认套件连续 3 次全通过（10 passed / 1 skipped）；真实模型场景单独 1 次通过（全场 45.1s）。收口全绿：shared 11、server 233 passed / 1 skipped、web 55、E2E 10 passed / 1 skipped；到 E2E 为止共 22 个提交，文档提交不计。

验证按风险分层：类型检查确认跨包契约，单测锁定纯规则与 reducer，集成测试覆盖数据库事务、REST 错误体与 SSE 补发顺序；真实模型只用于有次数上限的受控冒烟与整场联调。

## 典型问题与解决路径

1. **种子回放像机械轮播。** 首版专家按 seat 顺序发言、次数相同，洞察立场对不上证据；根因是样例数据只满足结构、不满足讨论质量。编排者于 03b 把交锋、发言次数差、抢答顺序、证据 seq 和 stanceTag 写成可验证要求，修种子补测试；提交 ef7421e 后回放成可信示例。
2. **Prompt 格式正确，讨论却不像圆桌。** 真实冒烟中专家很少反驳，主持人猜错嘉宾名单，洞察为空而总结仍说有共识；根因是模型只看到匿名别名、出价缺少立场关系、洞察只拿新增发言。编排者把阵容名册、上一条发言与立场、洞察窗口写进规格，续派补 Prompt 和测试，并把引用、病句、重复与错误归属写成断言。
3. **控制接口会覆盖实时状态。** 用户点暂停时，页面曾用首次载入快照替换 reducer，已由 SSE 收到的发言与洞察随之消失；原因是控制响应复用过期快照。续派改为只合并 discussion 并比较更新时间；总结竞态另由 summary.completed 推进时间戳、避免旧响应倒退修复，测试等待 SSE 连接实际建立。
4. **E2E 的洞察顺序会漂移。** 固定种子后，同一场讨论共识/分歧立场顺序两次运行间仍不一致，提示词洞察编号不稳定；根因是仓库读取按 participant_id（随机 UUID）排序、同毫秒洞察按随机 id 决胜，Runner ref 映射与提示词编号口径错位。解决：按座位与 created_at、rowid 排序，Runner 与提示词共用同一排序函数，用服务端种子固定讨论 ID。结果：同一种子两场逐条一致，retries 0。

## 我对工程化 AI 开发的理解

个人理解是把ai不确定的输出加上一些要求，限制，验证等等，使其输出稳定可靠，并将其做成一个业务系统。

- **Prompt 是有版本的工程输入。** 每阶段原文留在 `docs/prompts/`，记录范围、验收与不能碰的目录；评审发现缺陷，追加精确续派，不让代理重写已完成部分。
- **规格先于行为变化。** 测试或实现暴露状态机、失败计数或模型路由歧义时，先说明决定并更新规格，同步测试与代码，保留可追溯的因果。
- **分层验证互相补位。** 单测检查规则，集成测试检查数据库、REST 与 SSE，截图和真人通读检查体验；任何一层都不能替代其他层。
- **并行必须有边界。** 任务分给不重叠文件范围，验证命令限定 workspace，避免 lockfile、工作区和服务状态同时改动。
- **安全约束进入流程而非口头提醒。** 密钥只留后端环境；隐藏推理不进入小窗、事件或日志；mock 与假值承担自动化验证。
